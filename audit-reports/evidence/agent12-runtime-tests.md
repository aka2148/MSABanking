## New defects found only at runtime

| ID | Sev | Finding | Evidence |
|---|---|---|---|
| RT-09 | P1 | **Timezone sensitivity of accrual dates (host JVM not UTC).** Running fd-account-service in an IST JVM stored `fia_accrual_date` as `2026-10-25 18:30:00` for a 26-Oct accrual (a day shift) and the accrual/clock endpoints then failed with **500 `DuplicateKeyException` on `uq_fd_interest_accrual_account_date`** (`Duplicate entry '2-2027-01-24 18:30:00.000000'`). Re-running with `-Duser.timezone=UTC` removed this class of error. The compose file sets `connectionTimeZone=UTC` for JDBC but not the JVM timezone; Docker images are normally UTC, so this bites **non-Docker/local runs and any host with a different TZ**. Also shows the accrual idempotency guard fails with a 500 instead of skipping when dates are shifted. | `runtime-logs/run1-IST-accrual-date-evidence.txt`, `fd-service-run1-IST-timezone-failure.log:38-40,219-221` |
