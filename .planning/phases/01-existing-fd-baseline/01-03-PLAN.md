<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted HTTP JSON → typed FD DTO | Caller-controlled numbers, identifiers, and status-like fields cross into the contract layer. |
| HTTP caller → `/fd/v1` controller | Unauthenticated or unauthorized callers may attempt to invoke account routes. |
| Test code/container → migration catalog | Schema verification must not accidentally use H2 or a tracked external credential. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Tampering | `CreateAccountContractRequest` / `UpdateAccountContractRequest` | mitigate | Use typed fields, Bean Validation, `BigDecimal`, and omit `status` from the update DTO/OpenAPI schema. |
| T-01-09 | Spoofing | `FdV1ContractController` | mitigate | Require `isAuthenticated()` at the controller boundary; resource ownership and actor derivation remain service-level requirements for the later mutation phases. |
| T-01-10 | Information disclosure | unsupported FD routes | mitigate | Retain the stable `ApiErrorResponse` without serializing entities or account data from unsupported operations. |
| T-01-11 | Tampering | PostgreSQL schema verification | mitigate | Run Flyway and rejection assertions against a containerized PostgreSQL instance, not H2 or a shared credentialed database. |
</threat_model>
