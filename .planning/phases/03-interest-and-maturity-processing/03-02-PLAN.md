<objective>
Implement accrual and maturity processing on the `/fd/v1` surface using the shared plan-01 calculator, and expose readable accrual results for the REST demonstration.

Purpose: This is the behavioral core of Phase 3 (LIFE-02 + CALC-02 application). An ACTIVE FD must accrue interest that can be read back, and must transition to MATURED with a final through-end-date calculation once its stored maturity date is reached — while PENDING and CLOSED accounts are rejected through the Phase 1 lifecycle boundary.
Output: `AccrualService`, `MaturityService`, typed accrual DTOs, four implemented `/fd/v1` endpoints (run accrual, list accrual, cumulative accrual, mature) with OpenAPI schemas, plus unit and contract tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | business_date, accountId, and auth identity cross here; rate/principal/dates never accepted from client |
| service→ledger | Accrual rows and MATURITY transaction written with server-computed amounts only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | T (Tampering) | runAccrual business_date | mitigate | Optional client date is clamped to min(businessDate, stored maturityDate); amounts always recomputed server-side with FdInterestCalculator — client values never persisted |
| T-03-05 | E (Elevation) | AccrualService/MaturityService holder check | mitigate | FdActorResolver.resolve(username) matched against primaryHolderId exactly like FundingService; mismatch throws AccessDeniedException before any state change |
| T-03-06 | T (Tampering) | matureAccount eligibility | mitigate | PENDING/CLOSED rejected via lifecycle state machine (InvalidFdTransitionException); pre-maturity-date requests rejected with InvalidInputException; final amounts recomputed through maturityDate, not trusted from stored estimate |
| T-03-07 | R (Repudiation) | MATURITY transaction row | mitigate | Maturity persists an fd_transactions MATURITY record with UTC timestamp, currency, and internal-record remark alongside the status transition |
| T-03-08 | I (Info disclosure) | listAccrual/cumulative reads | mitigate | Holder ownership checked on reads; responses are explicit DTOs, never serialized entities |
</threat_model>
