<objective>
Build the single shared BigDecimal money-math core and the accrual persistence foundation that accrual and maturity processing both consume.

Purpose: CALC-01 and CALC-02 require one consistent, explainable decimal policy. Without a shared calculator, accrual and maturity would each re-derive the formula and drift from the booking estimate. This plan also maps the existing `fd_interest_accrual` table and provisions the transaction codes maturity/accrual need, so plan 03-02 can focus purely on service behavior and API wiring.
Output: `FdInterestCalculator` domain service with unit tests, `FdInterestAccrual` entity + repository with schema test, and V8 Flyway migration.
</objective>

```java
static BigDecimal maturityEstimate(BigDecimal principal, BigDecimal annualRate,
                                   LocalDate openDate, LocalDate maturityDate) {
    long days = ChronoUnit.DAYS.between(openDate, maturityDate);
    return principal.add(principal.multiply(annualRate)
                    .multiply(BigDecimal.valueOf(days))
                    .divide(BigDecimal.valueOf(365), 12, RoundingMode.HALF_UP))
            .setScale(2, RoundingMode.HALF_UP);
}
```
